### Flight Recorder Project 概要書

#### 1. 目的（Purpose）

AI時代の開発プロセスにおける「レビューの質の変革」と「暗黙知の資産化」を達成する。

* **「翻訳コスト」の解消:**
「人間A（指示者）の意図」を「人間B（レビュアー）」が生成コードから逆算・推測する無駄を排除する。
* **レビュー対象のシフト:**
コードの字面（Result）だけでなく、**「プロンプトによる指示」「思考プロセス」「試行錯誤の履歴」（Source & Process）**をレビュー対象とし、本質的な仕様確認と品質担保を行う。
* **同期確認会の実現:**
非同期のPRレビュー（Gatekeeping）から、チーム全員でプロセスを再生・検証する同期会（Co-designing）へ移行し、知識共有と合意形成を加速させる。

#### 2. 全体構想（Overall Concept）

Coding Agentの開発フローに、透明な「記録係（Sidecar）」を随伴させ、成果物とプロセスをセットで管理するエコシステム。

* **The Recorder (Observer):**
* Coding Agentの横で稼働する、独立した記録プロセス。
* ユーザーの指示（Prompt）、Agentの思考（Chain of Thought）、ツール実行、エラー、そして最終的なコード変更を「時系列のセッションログ」として自動記録する。


* **The Storage (Black Box):**
* プロジェクトごとのローカル環境に蓄積される構造化データ（SQLite等）。
* コードのバージョン管理（Git）とは分離し、より詳細でコンテキストリッチな情報を保持する。


* **The Viewer (Replay):**
* 確認会で使用する再生インターフェース。
* 「どの指示で、なぜそのコードになったか」を可視化し、チームが議論すべき「苦戦ポイント」や「仕様変更点」をハイライトする。



#### 3. 設計哲学（Design Philosophy）

**"Local First, Unix Philosophy, Sidecar Pattern"**

* **Local First & Privacy:**
* データは全てローカル（開発者のマシン内）で完結・保存される。
* 外部クラウドへの依存を排除し、プライバシーとレスポンス速度を最優先する。共有（Upload）は意図的なアクション（Export）としてのみ行われる。


* **Unix Philosophy (Do One Thing Well):**
* このツールは「記録と取り出し」のみに特化する。
* 複雑な分析やリッチなUIは持たず、他のツール（ViewerやCLI）とパイプラインで連携できるシンプルで堅牢なインターフェースを持つ。


* **Sidecar / Observer Pattern:**
* Coding Agent（Main）のコンテキストやリソースを圧迫しない。
* Agentの主観（要約）に頼らず、客観的な事実（Raw Log）を記録することで、情報の正確性と「言った・言わない」の証跡能力を担保する。



#### 4. まとめ（Summary）

本プロジェクトは、ソフトウェア開発における「成果物」の定義をアップデートする試みです。

これまでは「ソースコード」のみが資産でしたが、Flight Recorderの導入により、**「ソースコード ＋ それを生み出したコンテキスト（プロンプトと対話の履歴）」**を真の資産と定義します。

これにより、チームは「誰が書いたか」という属人性を超えて、「チームとしてどう指示し、どう承認したか」という**集合知的な開発体制**へ移行できます。これは単なるツール導入ではなく、Coding Agentを前提とした新しいエンジニアリング文化の礎となるものです。
